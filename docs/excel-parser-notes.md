# Excel 解析器边界实测笔记（openpyxl_loader.py）

> 目的：对 AC-PARSE-05 要求的四类边界逐项实测，记录真实输出与设计决策，作为解析器行为的可追溯记录。
> 测试方法：构造 6 场景 xlsx（正常表 / 单列长文本 / 只有表头 / 空行 / 表头行合并 / 数据行合并），直接调用 `OpenpyxlExcelLoader.load()`，共 11 个 Document，观察逐场景输出。

## 一、场景与结果总表

| 场景 | 触发条件 | 实测结果 | 判定 |
|---|---|---|---|
| S1 正常表（int / float 整数值 / 小数 / None 混合） | 表头非空格 ≥2 且数据行 ≥2 | 每行一个 Document，`字段: 值` 结构 | 符合 AC-PARSE-02 |
| S2 单列长文本 | 表头非空格 = 1（< 2） | 整表单文档，不拆行 | 防误拆，符合预期 |
| S3 只有表头 | 数据行 = 1 | 整表单文档 | 光杆表头无拆分意义 |
| S4 空行穿插 | 行全空（`any(cells)` = False） | 空行跳过，`row_id` 保留真实 Excel 行号（实测 A产品=3、B产品=5） | 可溯源定位 |
| S5 表头行横向合并单元格 | 合并格非空表头单元格只剩 1 | 误判无表头 → 整表退化单文档 | **已知限制一** |
| S6 数据行合并单元格（横向 + 纵向） | 合并格左上值/None 分布 | 横向合并左上值正常落入本行；**纵向合并延续行拿到 None → 缺主字段孤儿块** | **已知限制二** |

## 二、关键设计决策实测验证

### 2.1 `_fmt_cell` 的三类值处理（S1 实测）

| 单元格输入 | 输出 | 目的 |
|---|---|---|
| `459.0`（float 且 is_integer） | `459` | 防 `.0` 进检索库：用户问"价格 459"字面不匹配 |
| `699.123`（真小数） | `699.123` | 保留精度 |
| `None` | 空串 → 该列整对不拼接 | 防 `"库存: "` 半截行污染向量 |
| 字符串 | strip 后原样 | 去首尾空格 |

### 2.2 表头判定红线：`has_header = 非空表头格 >= 2 and len(data_rows) > 1`

防两类误拆：
- **单列长文本**（S2）：备忘录/日志类内容不是"字段-值"结构，硬拆产生 `列1: xxx` 无信息量块。退化保上下文。
- **光杆表头**（S3）：无数据行则拆分无意义。

### 2.3 行号保真：`enumerate(iter_rows, start=1)` 记录真实 Excel 行号

空行被过滤，但计数不中断——S4 实测数据行 row_id 为 3 和 5（Excel 真实行号），非连续。检索命中后 metadata 的 `row_id` 可直接用于定位回原表。

## 三、已知限制

### 限制一：表头行合并单元格触发误判退化（S5 实测）

**现象**：横向合并的表头行（如 A1:B1 merge）在 openpyxl 中只有左上格有值，其余为 None → 非空表头单元格数 = 1 → 不满足 ≥2 红线 → 走退化模式，整表变单文档。

**影响范围**：仅"表头行合并"场景。数据行的**横向**合并不受影响（左上值正常落入本行，见 S6 doc[9]）。

**安全性与权衡**：
- 退化模式不丢数据，只是检索粒度从行级变整表级——失败方式安全（fail-safe，非 fail-loss）。
- 修复思路（未实施）：表头识别前对合并行做左上值填充（`ws.unmerged_cells` 逆操作），或放宽红线为"非空格 ≥1 且无后续数据行结构冲突"。两者都引入额外复杂度，当前量级下收益不足，标记为已知限制。

### 限制二：纵向合并延续行缺主字段（S6 实测）

**现象**：纵向合并（如 A3:A4 merge）的值只挂在首行（A3），延续行 A4 在 openpyxl 中为 None → `None → 空串 → 该列不拼接` → 延续行产出缺关键字段的孤儿块（实测第 4 行只剩 `规格: 标准版 / 数量: 5`，丢失 `名称`）。

**影响范围**：依赖纵向合并表达"同类延续"语义的表格（如合并同名的分类列）。孤板块内容仍真实，只是脱离主键上下文，向量检索时语义不完整。

**修复思路（未实施）**：行转块前对纵向合并区做向下填充（forward-fill 左上值）。同样因复杂度与收益权衡暂不实施。

**共性说明**：两条限制的根因相同——openpyxl 的合并单元格只在左上角锚点存值。差异仅在合并方向决定了锚点值落在本行（横向，无害）还是只落在首行（纵向，后续行缺失）。

### 载入参数的两条防线

- `data_only=True`：读公式计算结果而非公式字符串。去掉则 `"=SUM(A1:A10)"` 文本直接进检索库——查询命中公式文本，答案与数据值脱节。
- `read_only=True` + `finally: wb.close()`：流式读取控内存；Windows 下句柄不释放会锁文件，同路径二次上传直接失败。

## 四、与 AC-PARSE-05 的对应

| AC 要求的四类边界 | 本笔记覆盖 | 结果 |
|---|---|---|
| 多 sheet 全入库 | S1-S6 每个 workbook 含 6 个 sheet 全部产出 Document | ✅ |
| 合并单元格 | S5 表头行合并（已知限制一）；S6 数据行横向合并正常 + 纵向合并延续行缺字段（已知限制二） | ⚠️ 两条已知限制 |
| 空行 | S4 跳过且行号保真 | ✅ |
| 数字与日期格式 | S1 `_fmt_cell` 三类值实测，无科学计数法残留 | ✅ |

结论：四类边界全部有实测记录；异常项（两种合并单元格场景）已按 AC-PARSE-05 要求标注为已知限制并给出权衡说明。
