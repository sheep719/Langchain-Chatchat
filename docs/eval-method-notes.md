# 检索评测方法论笔记

> 目的：记录本 fork 评测体系的设计决策与验证方法，作为 eval-results.md 数字的方法学依据。
> 测试集：`evaluation/testset.json`（20 题，AC-EVAL-01）
> 脚本：`evaluation/eval_retrieval.py`（离线直读 FAISS，不依赖 API 服务）

## 一、测试集设计：为什么这么出题

### 1.1 问题必须改写，禁止照抄文档原句

若问题与文档原句字面相同，BM25 通道词项完全对齐，等于白给——实验将无法区分"关键词命中"与"语义理解"两种检索能力，混合检索的对比结论失真。20 题全部为改写（paraphrase），如文档写"vLLM 是高效推理引擎"，问题问"推理框架有哪些选择"。

### 1.2 三分难度构成

| 段 | 题号 | 设计意图 |
|---|---|---|
| 关键词可命中 | Q01-06 | BM25 通道的基本盘（专有名词/原词） |
| 需语义理解 | Q07-13 | 向量通道的基本盘（改写后无字面重叠） |
| 刁钻题 | Q14-20 | 跨文档干扰、正确答案在别处（考排序区分度） |

每题附 `keywords`（期望文档的判定关键词：在期望文档出现、其他文档少出现），命中判定见脚本 `hit()`：关键词原文出现或去空格后出现即命中。

### 1.3 top_k = 3 与生产一致

检索结果直接作为 LLM 生成上下文，top_k 过大稀释上下文、过小丢召回；3 是该知识库规模下的生产值，评测与线上行为对齐。

## 二、指标定义（与脚本实现一致）

- **Hit@K**：期望 chunk 出现在检索结果前 K 位计 1，占比即命中率
- **MRR**（Mean Reciprocal Rank）：每题命中排名倒数（1/rank）的平均；**未命中计 0**
- 为什么同时报两个：Hit@3 是"及格线"（进了 top3 生成就有机会用上），MRR 是排序质量细粒度——第 1 名和第 3 名都算 Hit@3，但 MRR 分别贡献 1.0 与 0.333，能区分"第一名命中"和"压线命中"

## 三、重跑一致性验证（AC-EVAL-03）

**验证方法**（2026-10-29 复验）：同库同测试集同 top_k，独立重跑 20 题 × 3 模式，与仓库原始结果比对。

| 验证维度 | 结果 |
|---|---|
| 9 个质量指标（Hit@1/Hit@3/MRR × 3 模式） | 全部一致 |
| 逐题排名 60 格（20 题 × 3 模式） | 逐格一致 |
| 平均耗时 | 有波动（vector 0.06→0.16s，rerank 2.25→2.18s） |

**为什么质量指标能逐格一致**：分词（jieba 确定性）、embedding（bge-m3 前向计算）、FAISS 检索（索引固定）全程无随机性、无网络依赖。
**为什么耗时不承诺一致**：CPU 调度与缓存状态是环境因素，耗时属环境相关测量值而非确定性计算——"可复现"指质量指标，不指耗时恒定。

## 四、逐题考古：三个代表题

### 4.1 Q03 / Q13：BM25 救回与 rerank 反坑（已知模式）

- Q03"推理框架有哪些选择"（keywords: vllm）：vector 未命中 → hybrid_rrf 第 2 名命中（BM25 词面救回）→ rerank 后第 3（仍在 top3）
- Q13"稀疏注意力相关技术有哪些"（keywords: flash-attention）：vector 未命中 → hybrid_rrf 第 2 名命中 → **rerank 后未命中**（双塔余弦把清单型目标块的排序挤出 top3，详见 eval-results.md 结论段）

### 4.2 Q18"python API 工具有哪些"：混合检索并非逐题全胜（值得注意的模式）

| 模式 | 排名 | 说明 |
|---|---|---|
| vector | 2 | 向量路已命中 |
| hybrid_rrf | **3（反而下降）** | BM25 引入的干扰块与目标块分数接近，RRF 融合把第 2 挤到第 3 |
| hybrid_rerank | **1（救回）** | rerank 余弦恰好把目标块顶回第 1 |

**结论**：三模式各有胜负题。hybrid_rrf 在 Q18 是负贡献（-1 位），在 Q03/Q13 是正贡献（miss→top3），总体净收益 +2 题。**"混合检索不是每题都更好"是诚实结论的一部分**：它对总体分布赢，不保证单题单调提升。
